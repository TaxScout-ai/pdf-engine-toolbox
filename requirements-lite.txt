# Dependencies for the text-only build of this service.
#
# WHY A SECOND FILE
#
# The Paddle stack is 719 MB on its own and drags in scipy, pandas,
# scikit-learn, modelscope and a second copy of OpenCV — about a gigabyte that
# PyMuPDF work never touches. Dropping it takes the image from 3.95 GB to
# 1.02 GB, a 74% cut, which is the difference between needing a big machine and
# not.
#
# It is worth having because most documents never need OCR. Across a
# 582-document corpus, 475 (81%) yield usable text through PyMuPDF alone; 82
# are scans that do need recognition. This build serves the 81%.
#
# It works with no code changes because every paddle import is lazy, inside the
# function that needs it (pdf_service.py:314, 1350, 2151). Verified against
# this build: the service starts, logs one warning at warm-up, answers /info
# and /text/extract normally, and an OCR request fails with
# "OCR requires paddleocr>=3.0 and paddlepaddle>=3.0 packages" instead of
# crashing or hanging.
#
# Keep in step with requirements.txt: this file is that one minus the Paddle
# stack and the test packages.
